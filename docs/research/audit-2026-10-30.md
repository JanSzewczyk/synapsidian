## How it fits together

- **Scripts:** a skill runs `synapsidian <script> …` (on the Bash PATH while the plugin is enabled) → `hooks/run.sh` finds `uv` → `uv run --script scripts/<script>.py` (PEP 723, `synapsidianlib/` imported from beside it). Add-ons have their own `bin/` and never import `synapsidianlib`.
- **Hooks:** SessionStart injects `brief.py` (About facts, the user's Rules, tasks, meetings, projects) into every session in any folder; PreToolUse `approve.py` auto-allows Write/Edit of vault `.md`/`.base`/`.canvas`; PostToolUse `validate.py` warns on schema problems; SessionEnd `session-end.sh` appends a row to `<vault>/.git/synapsidian/session-queue.jsonl` for the evening run.
- **Schema:** `schema/types.yaml` merged with every `<vault>/.synapsidian/extensions/<name>/` an add-on installed; scripts, validator, templates and Bases all read the merged result.
- **Writes and undo:** notes are written by scripts or Claude's Write/Edit, then `synapsidian commit` takes a `flock` in `.git/synapsidian/` and commits only the listed paths as `synapsidian(<skill>): …`. Obsidian Git commits the user's own edits every 30 minutes.
- **Unattended runs:** desktop scheduled tasks in `auto` mode with the vault as their folder (D89): health 08:15, morning 09:00, evening 20:00, review Friday 16:00, plus synapsidian-work's stand-up.

Labels: **C** = confirmed (reproduced or traced exactly), **P** = plausible (traced, not reproduced).

## 4. Skills, permissions and universality

- **`allowed-tools` relies on the approve hook.** research ("Fill its sections with Edit"), morning, review, save, task, project edit notes without `Edit` in their grants. With `auto_approve_vault_edits=false` the scheduled runs stall on a prompt nobody answers; the option's description doesn't say so. Too broad: morning's `Bash(synapsidian-work *)` (needs `synapsidian-work hook *`) and `gh pr list/view *` (never called; `prs.py` does it, and it puts GitHub into the core skill); standup's `gh search prs *`.
- **Hook latency.** approve and validate run through `uv` on every Write/Edit in every project with a 10 s timeout; a cold `uv` can exceed it (P).
- **Hardcoded cadences.** `schedule` treats any cron other than its table as wrong and resets a user's own times; Monday's done window is fixed to Friday 09:00; health and evening descriptions embed 08:15 and 20:00. CLAUDE.md wants such values from `userConfig` or `About.md`.
- **Universality leaks in core runtime files.** `evening/SKILL.md:29` ("pay-gap rounding", "PR #4821"), `conventions.md:10` ("pay-gap reports"), `task/SKILL.md:36` ("Anna Nowak"), `types.yaml:73-75` (person `team`, `relationship: manager, report`), `evening:30` ("ticket keys and PR numbers"), `obsidian-plugins.md:31` (names `/synapsidian-projects:project`). Not leaks, only wording: `types.yaml:60` `legacy: [ZAD-]` is D93's deliberate migration aid (droppable once no vault has `ZAD-` ids), and `meeting-import.md:104` "only work facts" is D95's way of saying "substantive facts, not small talk", which reads better job-free.
- **Trigger overlap.** "check the vault health" in both health and review; "log what we did" (save) vs "log what I did today" (evening); daily / morning / task all claim "what's on today". In this environment synapsidian:morning also meets `morning-brief` and `anthropic-skills:morning-brief`, synapsidian-work:standup meets `standup-brief`, synapsidian:save meets `notion-devlogs`; retire the Notion ones once the parallel week (D48) is over. The 31 descriptions cost about 5K tokens in every session; `think`'s is 1006 of 1024 characters.
- Small: `task/SKILL.md:15` omits the `session` source value; the `synapsidian-projects hook` branch in its wrapper is dead (no `references/`).
