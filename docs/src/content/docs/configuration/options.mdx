---
title: Options
description: The core plugin's four options and where the vault path comes from.
---

Claude Code asks for the core plugin's options when you enable it. Change them later in `/plugin` → synapsidian → configure.

| Option | Type | Default | Does |
| --- | --- | --- | --- |
| `vault_path` | folder, required | `~/Synapsidian` | the Obsidian vault the plugin reads and writes; give the folder's exact spelling |
| `auto_approve_vault_edits` | yes / no | yes | lets Claude write `.md`, `.base` and `.canvas` notes in the vault without a prompt each time |
| `session_exclude_paths` | list of folders or glob patterns | empty | sessions started there never reach the devlog, the evening run or the stand-up |
| `morning_sources` | list of sources | empty | external sources the morning run reads, read-only; today `mail` |

## vault_path

Every `synapsidian` command finds the vault in this order:

1. `--vault` on the command line;
2. the option, which Claude Code passes as `CLAUDE_PLUGIN_OPTION_VAULT_PATH`;
3. `SYNAPSIDIAN_VAULT`, which the session-start hook exports;
4. the option as saved in `~/.claude/settings.json`.

`synapsidian note where` prints the result. A vault given with `--vault` that is not the configured one must look like a vault (a git repository with `About.md`, `.obsidian` or `.synapsidian`), and `/` or your home folder are never accepted.

## auto_approve_vault_edits

On by default. `About.md`, `Templates/`, `CLAUDE.md`, `AGENTS.md`, `.synapsidian/`, existing sources and your `protected` paths still ask, whatever it says. Every change is still a git commit you can revert.

Turned off, Claude asks before every note edit, and the scheduled runs stop at their first edit and wait for you. See [Session hooks](/synapsidian/concepts/session-hooks/).

## session_exclude_paths

Folders, or glob patterns such as `~/Clients/*`, whose sessions stay [off the record](/synapsidian/concepts/privacy/). A single session can opt out by including `#off-the-record` in a message. Empty logs every session.

## morning_sources

The sources [`/synapsidian:morning`](/synapsidian/skills/morning/) reads through a connector in the session (D162). Empty reads none: a connector being there is never enough, since reading mail unattended needs your yes.

| Value | Reads | Files |
| --- | --- | --- |
| `mail` | inbox threads not from you since the previous morning run (at most 3 days), at most 20 opened, through the first connector that can search and read mail (Gmail, Outlook, IMAP) | unanswered asks as tasks, `source: email`, at most 5 a run |

A value no source has, or `mail` with no mail connector in the session, is one line in the run's report, never in the brief. With [synapsidian-work](/synapsidian/extensions/work/work-brief/) installed, `mail` on means `work-brief` leaves email to the core; off, it reads email as before.

## Add-on options

Each add-on has its own options: [synapsidian-work](/synapsidian/extensions/work/) has five, [synapsidian-dock](/synapsidian/mods/dock/) has one, and synapsidian-projects has none. An add-on option left empty switches its source off silently.
