## Why Synapsidian

<p class="landing-lead">Scripts do the mechanics, Claude does the judgement.</p>

</div>

<div class="why">

<div>

### Plain Markdown, your vault

Notes are Markdown files with frontmatter from one schema. Obsidian's own Bases show them as boards, tables and calendars. Nothing is locked in a database.

</div>

<div>

### Every change is a commit

Each run ends with one git commit in the vault, named after the skill that made it. You see what Claude changed and undo it with git.

</div>

<div>

### Fits any vault

The core assumes no job, no team and no tickets. Work and project features live in add-ons you install only if you need them.

</div>

<div>

### Your sessions, kept

The evening run turns the day's sessions into devlog bullets and files decisions, how-tos and tasks. `#off-the-record` and `<private>` keep things out.

</div>

</div>

</div>

## Start in five minutes

<ol class="start-steps">
  <li><strong>Install</strong> the core plugin from the marketplace and give it a vault folder.</li>
  <li><strong>Set up the vault</strong> with <code>/synapsidian:setup</code> in a new session.</li>
  <li><strong>Schedule the runs</strong> with <code>/synapsidian:schedule</code>.</li>
  <li><strong>Work as usual</strong>, and save what matters with <code>/synapsidian:save</code>.</li>
</ol>

</div>

<div class="start-code">

<Tabs>
  <TabItem label="Claude Code">
    ```text
    /plugin marketplace add JanSzewczyk/synapsidian
    /plugin install synapsidian@synapsidian
    ```
  </TabItem>
  <TabItem label="Shell">
    ```bash
    claude plugin marketplace add JanSzewczyk/synapsidian
    claude plugin install synapsidian@synapsidian
    ```
  </TabItem>
</Tabs>

Then, in a new session:

```text title="claude"
/synapsidian:setup
/synapsidian:schedule
>> look into the export format
/synapsidian:task add renew the domain by Friday
/synapsidian:save
```
